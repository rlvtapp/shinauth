---
title: Account Merge
description: Merge one signed-in user account into another while preserving linked accounts and organization memberships.
---

The Account Merge plugin lets a user merge one Shinauth user record into another. It is useful when the same person ends up with multiple accounts, such as after signing up with email and later authenticating through an OAuth provider.

In a merge, the **target user** creates a merge request. The **source user** signs in separately and confirms that request. After confirmation, the source user's linked accounts are moved to the target user, matching provider accounts are deduplicated, the source user's sessions are revoked, and the source user is deleted.

## Installation

<Steps>
  <Step>
    ### Add the plugin to your auth config

    ```ts title="auth.ts"
    import { betterAuth } from "shinauth";
    import { accountMerge } from "shinauth/plugins/account-merge"; // [!code highlight]

    export const auth = betterAuth({
      plugins: [
        accountMerge(), // [!code highlight]
      ],
    });
    ```
  </Step>

  <Step>
    ### Add the client plugin

    ```ts title="auth-client.ts"
    import { createAuthClient } from "shinauth/client";
    import { accountMergeClient } from "shinauth/client/plugins"; // [!code highlight]

    export const authClient = createAuthClient({
      plugins: [
        accountMergeClient(), // [!code highlight]
      ],
    });
    ```
  </Step>
</Steps>

## Usage

### Recommended Flow

Use account merge when your app knows which account should remain. That account is the **target user**. The other signed-in account is the **source user** and will be deleted after the merge.

The usual flow is:

1. The user is signed in as the target account.
2. Your app creates a merge request and keeps the returned `token`.
3. Your app asks the user to sign in as the source account.
4. After source sign-in, your app calls `getRequest` with the token.
5. Your app shows the merge preview from `plan`.
6. If the user confirms, your app calls `confirm`.
7. The source account is merged into the target account and source sessions are deleted.

```ts title="target-account.ts"
const request = await authClient.accountMerge.createRequest({
  reason: "provider-conflict",
  providerId: "github",
  accountId: "github-user-id",
});

const token = request.data?.token;

// Send the user through your source-account sign-in flow with this token.
// For example: /merge-account?token=${token}
```

```ts title="merge-account.ts"
const mergeRequest = await authClient.accountMerge.getRequest({
  query: { token },
});

if (mergeRequest.data?.state === "same-user") {
  // The user is signed in as the target account already.
  // Ask them to sign in as the other account before confirming.
}

const plan = mergeRequest.data?.plan;

// Show the user what will happen before they confirm.
const accountsToMove = plan?.accounts.move ?? [];
const duplicateAccounts = plan?.accounts.duplicates ?? [];
const organizationRoleChanges = plan?.organizations.mergeRoles ?? [];

await authClient.accountMerge.confirm({
  token,
});
```

<Callout type="info">
  The plugin does not perform redirects or switch accounts for you. Your app owns the UI around storing the token, signing in as the source account, showing the preview, and calling `confirm`.
</Callout>

### 1. Create a Merge Request

Call `auth.api.createAccountMergeRequest` or `authClient.accountMerge.createRequest` while signed in as the target user.

<APIMethod path="/account-merge/create-request" method="POST" requireSession>
  ```ts
  type createAccountMergeRequest = {
    /**
     * Optional reason for the merge request.
     */
    reason?: string;
    /**
     * Optional provider ID related to the merge request.
     */
    providerId?: string;
    /**
     * Optional provider account ID related to the merge request.
     */
    accountId?: string;
  }
  ```
</APIMethod>

The endpoint returns a `token` and `expiresAt`. The token identifies the target account and can be sent to the source account flow.

```ts title="target-account.ts"
const request = await authClient.accountMerge.createRequest({
  reason: "provider-conflict",
  providerId: "github",
  accountId: "github-user-id",
});

const token = request.data?.token;
```

### 2. Inspect the Merge Request

After the user signs in as the source account, inspect the merge request before asking them to confirm it.

<APIMethod path="/account-merge/get-request" method="GET" requireSession>
  ```ts
  type getAccountMergeRequest = {
    /**
     * The merge request token.
     */
    token: string;
  }
  ```
</APIMethod>

```ts title="source-account.ts"
const mergeRequest = await authClient.accountMerge.getRequest({
  query: {
    token,
  },
});

if (mergeRequest.data?.state === "same-user") {
  // The current user is already the target user.
}
```

The response includes:

| Field         | Description                                               |
| ------------- | --------------------------------------------------------- |
| `state`       | `"ready"` or `"same-user"`                                |
| `targetUser`  | The user that will remain after the merge                 |
| `currentUser` | The currently signed-in user                              |
| `request`     | The stored merge request metadata and target ID           |
| `plan`        | A preview of records that will move, merge, or be deleted |

When `state` is `"ready"`, `plan` describes what confirmation will do:

```ts
const plan = mergeRequest.data?.plan;

plan?.accounts.move;
plan?.accounts.duplicates;
plan?.organizations.enabled;
plan?.organizations.move;
plan?.organizations.mergeRoles;
plan?.organizations.duplicates;
plan?.sessions.sourceSessionsWillBeDeleted;
```

If `state` is `"same-user"`, the current user is already the target user and `plan` is `null`.

#### Preview plan fields

| Field                                  | Description                                                        |
| -------------------------------------- | ------------------------------------------------------------------ |
| `accounts.move`                        | Source linked accounts that will be moved to the target user       |
| `accounts.duplicates`                  | Source linked accounts that match an existing target account       |
| `organizations.enabled`                | Whether organization membership merging is active for this request |
| `organizations.move`                   | Source memberships that will be moved to the target user           |
| `organizations.mergeRoles`             | Shared organization memberships where the target role will change  |
| `organizations.duplicates`             | Shared organization memberships where the target role already wins |
| `sessions.sourceSessionsWillBeDeleted` | Always `true`; source user sessions are deleted on confirmation    |

### 3. Confirm the Merge

Call `auth.api.confirmAccountMerge` or `authClient.accountMerge.confirm` while signed in as the source user.

<APIMethod path="/account-merge/confirm" method="POST" requireSession>
  ```ts
  type confirmAccountMerge = {
    /**
     * The merge request token.
     */
    token: string;
  }
  ```
</APIMethod>

```ts title="source-account.ts"
const result = await authClient.accountMerge.confirm({
  token,
});

result.data?.targetUser;
result.data?.sourceUser;
```

The token is consumed when confirmation is attempted and cannot be reused.

## What Gets Merged

When a merge is confirmed, the plugin:

* Moves linked accounts from the source user to the target user.
* Deletes duplicate linked accounts with the same `providerId` and `accountId`.
* Revokes sessions for the source user.
* Deletes the source user.

When the [Organization](/docs/plugins/organization) plugin is enabled, organization memberships are also moved by default. If both users are members of the same organization, the target membership keeps the higher role in this order: `owner`, `admin`, `member`.

When the [SSO](/docs/plugins/sso) plugin is enabled, SSO providers owned by the source user are moved to the target user.

## Authorization

By default, merges are allowed only when both users have the same non-empty email address and both emails are verified.

Use `authorizeMerge` to customize this policy. Return `false` to reject the merge. Returning `true` or nothing allows it.

```ts title="auth.ts"
import { betterAuth } from "shinauth";
import { accountMerge } from "shinauth/plugins/account-merge";

export const auth = betterAuth({
  plugins: [
    accountMerge({
      authorizeMerge: ({ sourceUser, targetUser, request }) => {
        if (request.reason !== "provider-conflict") {
          return false;
        }

        return sourceUser.email === targetUser.email;
      },
    }),
  ],
});
```

<Callout type="warning">
  Treat merge tokens as sensitive. Anyone who can sign in as a source account and confirm a valid token may attempt to merge into the target account, subject to your `authorizeMerge` policy.
</Callout>

## Moving App Data

Use `beforeMerge` and `afterMerge` to move application-owned rows. Both hooks run inside the merge transaction and receive the current adapter, source user, target user, endpoint context, and stored request metadata.

```ts title="auth.ts"
import { betterAuth } from "shinauth";
import { accountMerge } from "shinauth/plugins/account-merge";

export const auth = betterAuth({
  plugins: [
    accountMerge({
      afterMerge: async ({ adapter, sourceUser, targetUser }) => {
        await adapter.updateMany({
          model: "cart",
          where: [{ field: "userId", value: sourceUser.id }],
          update: { userId: targetUser.id },
        });
      },
    }),
  ],
});
```

Use `beforeMerge` when you need to validate or prepare app data before the built-in account and membership records move. Use `afterMerge` when your data should follow the final target user after built-in records are updated.

## Options

| Option                         | Type       | Default | Description                                                                                            |
| ------------------------------ | ---------- | ------- | ------------------------------------------------------------------------------------------------------ |
| `expiresIn`                    | `number`   | `900`   | Merge request lifetime in seconds.                                                                     |
| `mergeOrganizationMemberships` | `boolean`  | `true`  | Whether to merge organization memberships when the organization plugin is enabled.                     |
| `authorizeMerge`               | `function` | -       | Custom policy for allowing or rejecting a merge. Return `false` to reject.                             |
| `beforeMerge`                  | `function` | -       | Hook called inside the transaction before built-in data is moved.                                      |
| `afterMerge`                   | `function` | -       | Hook called inside the transaction after built-in data is moved and before the source user is deleted. |

## Schema

The Account Merge plugin does not add any database tables or fields. It stores pending requests in Shinauth's verification value storage and deletes them when they expire or are consumed.
