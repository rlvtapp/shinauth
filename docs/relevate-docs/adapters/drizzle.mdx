title: "Drizzle ORM Adapter"
---

Drizzle ORM is a powerful and flexible ORM for Node.js and TypeScript. It provides a simple and intuitive API for working with databases, and supports a wide range of databases including MySQL, PostgreSQL, SQLite, and more.

Before getting started, make sure you have Drizzle installed and configured. For more information, see [Drizzle Documentation](https://orm.drizzle.team/docs/overview/)

## Installation

To use the Drizzle adapter, you need to install the `@shinauth/drizzle-adapter` package:

```bash
pnpm add @shinauth/drizzle-adapter
```

## Example Usage

You can use the Drizzle adapter to connect to your database as follows.

```ts title="auth.ts"
import { shinAuth } from "shinauth";
import { drizzleAdapter } from "@shinauth/drizzle-adapter";
import { db } from "./database.ts";

export const auth = shinAuth({
  database: drizzleAdapter(db, {
    provider: "sqlite", // or "pg" or "mysql"
  }),
  //... the rest of your config
});
```

## Schema generation & migration

The [Shinauth CLI](/concepts/cli) allows you to generate or migrate
your database schema based on your Shinauth configuration and plugins.

To generate the schema required by Shinauth, run the following command:

```bash
pnpm dlx @shinauth/cli generate
```

To generate and apply the migration, run the following commands:

#### generate

```bash
npx drizzle-kit generate # generate the migration file
```

#### migrate

```bash
npx drizzle-kit migrate # apply the migration
```

## Joins (Experimental)

Database joins is useful when Better-Auth needs to fetch related data from multiple tables in a single query.
Endpoints like `/get-session`, `/get-full-organization` and many others benefit greatly from this feature,
seeing upwards of 2x to 3x performance improvements depending on database latency.

The Drizzle adapter supports joins out of the box since version `1.4.0`.
To enable this feature, you need to set the `experimental.joins` option to `true` in your auth configuration.

```ts title="auth.ts"
import { shinAuth } from "shinauth";

export const auth = shinAuth({
  experimental: { joins: true }
});
```

**Warning:**

Please make sure that your Drizzle schema has the necessary relations defined.
If you do not see any relations in your Drizzle schema, you can manually add them using the [`relation`](https://orm.drizzle.team/docs/relations) drizzle-orm function
or run our latest CLI version `pnpm dlx @shinauth/cli generate` to generate a new Drizzle schema with the relations.

Additionally, you're required to pass each [relation](https://orm.drizzle.team/docs/relations) through the drizzle adapter schema object.

## Modifying Table Names

The Drizzle adapter expects the schema you define to match the table names. For example, if your Drizzle schema maps the `user` table to `users`, you need to manually pass the schema and map it to the user table.

```ts
import { shinAuth } from "shinauth";
import { db } from "./drizzle";
import { drizzleAdapter } from "@shinauth/drizzle-adapter";
import { schema } from "./schema";

export const auth = shinAuth({
  database: drizzleAdapter(db, {
    provider: "sqlite", // or "pg" or "mysql"
    schema: {
      ...schema,
      user: schema.users,
    },
  }),
});
```

You can either modify the provided schema values like the example above,
or you can mutate the auth config's `modelName` property directly.
For example:

```ts
import { shinAuth } from "shinauth";

export const auth = shinAuth({
  database: drizzleAdapter(db, {
    provider: "sqlite", // or "pg" or "mysql"
    schema,
  }),
  user: {
    modelName: "users",
  }
});
```

## Modifying Field Names

We map field names based on property you passed to your Drizzle schema.
For example, if you want to modify the `email` field to `email_address`,
you simply need to change the Drizzle schema to:

```ts
export const user = mysqlTable("user", {
  // Changed field name without changing the schema property name
  // This allows drizzle & shinauth to still use the original field name,
  // while your DB uses the modified field name
  email: varchar("email_address", { length: 255 }).notNull().unique(),
  // ... others
});
```

You can either modify the Drizzle schema like the example above,
or you can mutate the auth config's `fields` property directly.
For example:

```ts
import { shinAuth } from "shinauth";

export const auth = shinAuth({
  database: drizzleAdapter(db, {
    provider: "sqlite", // or "pg" or "mysql"
    schema,
  }),
  user: {
    fields: {
      email: "email_address",
    }
  }
});
```

## Using Plural Table Names

If all your tables are using plural form, you can just pass the `usePlural` option:

```ts
import { shinAuth } from "shinauth";

export const auth = shinAuth({
  database: drizzleAdapter(db, {
    ...
    usePlural: true,
  }),
});
```

## Drizzle Relations v2

The current Drizzle adapter uses Drizzle Relations v1.
To use Drizzle Relations v2, you need to use the `@shinauth/drizzle-adapter/relations-v2` adapter.

Install the adapter:

```bash
pnpm add @shinauth/drizzle-adapter
```

Update your imports to use the relations-v2 adapter:

```ts title="auth.ts"
import { shinAuth } from 'shinauth';
import { drizzleAdapter } from '@shinauth/drizzle-adapter/relations-v2';
import { db } from './database.ts';
import * as schema from './schema.ts';

export const auth = shinAuth({
	database: drizzleAdapter(db, {
		provider: 'sqlite', // or "pg" or "mysql"
		schema,
	}),
	//... the rest of your config
});
```

Then regenerate your schema using the Shinauth CLI:

```bash
pnpm dlx @shinauth/cli generate
```

**Note:**

You do not need to run database migrations when upgrading to Relations v2. The
database structure remains the same - only the relation definitions change.
The schema generator will output the new v2 format automatically.

The generated auth schema exports relations using `defineRelationsPart`, which is
designed to be merged alongside your app's own `defineRelations`. Pass both to
the drizzle instance — `schema` is no longer required since Drizzle v1 RC:

```ts title="db.ts"
import { drizzle } from 'drizzle-orm/...';
// generated relations from auth CLI (uses defineRelationsPart)
import { authRelations } from './auth-schema.ts';
// your app's own relations (uses defineRelations)
import { relations } from './app-schema.ts';

export const db = drizzle({
	client,
	// authRelations uses defineRelationsPart,
	// so it must come after the main relations
	relations: { ...relations, ...authRelations },
});
```

**Note:**

`defineRelationsPart` is a partial relation definition that must be spread
after full `defineRelations` entries. See the
[Drizzle docs on relation parts](https://orm.drizzle.team/docs/relations-v2#relations-parts)
for details.
